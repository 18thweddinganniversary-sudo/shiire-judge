# せどりGO 買付け結果記録 Design

## Goal
候補探索と店頭最終判定の後に、ユーザー自身が選んだ「買った / 見送った」を端末内へ記録し、次回の振り返りに使える最小機能を追加する。

## Product principles
- サポート優先。アプリは買付けを命令しない。
- 最終判断は常にユーザー。
- 既存のGO/見送り/判定不能はデータ判定であり、ユーザーの実際の買付け結果とは別フィールドで保存する。
- 合格済みの候補探索、Keepa token制御、店頭判定ロジックは変更しない。

## Minimal record
- id
- jan
- productName
- storeCost
- appVerdict (`GO` / `見送り` / `判定不能`)
- userResult (`bought` / `skipped`)
- recordedAt

## Storage
Phase 1はlocalStorageのみ。外部アカウントやクラウド同期は追加しない。

## UX
店頭判定の詳細シートに、判定結果が出た後だけ「買った」「見送った」の2操作を置く。押した結果だけを保存する。未入力価格や判定不能でもユーザーが見送った事実は保存できるが、「買った」は店頭価格が正の数で入力済みの場合だけ許可する。

## History
直近の買付け記録を端末内で保持する。今回の最小実装では保存コアと既存詳細シートからの記録操作を優先し、大規模な集計画面は追加しない。

## Acceptance
- 記録データを正規化して保存できる。
- 不正なJAN/結果/価格を保存しない。
- boughtは正の店頭価格必須。
- skippedは価格なしでも保存可能。
- 既存判定とユーザー結果を混同しない。
- localStorage破損時にアプリ全体を壊さない。
